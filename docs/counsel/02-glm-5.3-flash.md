## Verdict
Sound with changes. The Codex bridge is designed against an undocumented protocol whose session model conflicts with eve's own durability model, and that is the load-bearing wall.

## Critical
- [3, D3, 1.4] `codex app-server` is not an OpenAI-compatible endpoint. It is a Codex-specific JSON-RPC protocol with its own thread state, own instructions, and its own tool set (the catalog shows `shell_type: unified_exec`). Task 1.4's "session reuse" conflicts with eve's durability model, which checkpoints and replays message history per turn and can compact it. If router threads map onto eve sessions, the two histories diverge after the first compaction or resume. If threads are per-request, "session reuse" does not exist. The fix: stateless mapping, one fresh Codex thread per `/v1/chat/completions` request, full history each time, drop session reuse from 1.4, and add process lifecycle to the task (spawn app-server once, restart on crash, kill with the router). Also unknown: whether arbitrary eve tool schemas survive the trip into Codex and back. Gate S4 on tool-call round-trip, not just one text turn.

## High
- [S1 vs R1] S1 runs `npx eve@latest init .` while R1 says pin the version. Scaffold with the pinned 0.54.3, or accept drift consciously.
- [D5, S6] Step-level model selection and subagent pinning are alternatives, not a pair. Per-step routing across providers splits one conversation's prefix across upstreams, so prompt caches never stay warm. Pick subagent pinning.
- [missing task] Nothing keeps the eve process and router alive: no launchd plists, no restart on crash, no post-reboot state. Phone reachability implies always-on. Add supervision tasks to Phase 1.
- [D2] Incoherent. "Proven translators where they earn it" is contradicted by D3 and D4, which reject both external proxies. The actual design is all-in-house adapters plus two CLIs. Rewrite D2 to say that.
- [R6] A fallback chain silently swaps models mid-conversation, changing behaviour and voiding cache. Restrict fallback to new turns with a user-visible notice logged in the trace.
- [1.4] Codex CLI auto-updates and the app-server protocol is not versioned for you. Pin or verify the CLI version in the registry, not just eve.

## Answers to the plan's open questions (its section 8)
1. One process. Per-subscription services multiply ports, bearer tokens and secret-handling surface for zero benefit; the registry already isolates upstreams as modules.
2. `codex app-server`, but consumed statelessly (fresh thread per request, full history). Per-turn `codex exec` is brittle output parsing and loses server-side context either way. ChatGPT session semantics live inside Codex regardless; do not try to mirror them in the router.
3. Markdown files as source of truth plus SQLite FTS5 for search. `defineState` is session-scoped, the wrong layer for cross-session memory. What breaks at 10k: retrieval quality, stale memories polluting prompts, and injection risk from old content, not storage.
4. Pin models per subagent. Step-level selection guarantees cache misses. Caches stay warm within a subagent because its history stays on one model at one provider.
5. Smallest v1: router with the OpenCode Go adapter only, `agent.ts`, `instructions.md`, memory tool, own `web_search`, web channel with tailnet bearer, one eval suite. Cut the Codex adapter, subagents, schedules, MCP, CLI bridges and microsandbox until after a week of real use. That still covers chat from the phone, memory, and research.
6. D2 is wrong as written (see High). D5 is half wrong: per-task selection is right, but only via subagents, never step-level, for cache reasons.

## What the plan is missing entirely
- Process supervision and always-on behaviour. Consequence: after any reboot or crash the phone gets connection failures, which is exactly the daily-use failure mode the macOS app exists to hide.
- Per-subscription usage accounting. Consequence: when the router starts failing over you cannot tell which subscription is exhausted; R6's mitigation is blind.
- A concurrency rule for two surfaces (Mac and phone) hitting one session. Consequence: interleaved turns either corrupt one conversation or queue in ways nobody decided.

## The one change that most improves this plan
Rewrite 1.4 and D3 as stateless Codex bridging, and extend S4 to verify a full tool-call round trip through `codex app-server` (eve tool schema in, function call out), not just one text turn. Reasoned benefit: tools are the entire point of an agent, and this is the single component where an unverified assumption (plain model turns, clean session reuse) would only fail after Phase 2 is built on top of it. One spike day now versus a router redesign in Phase 2.
