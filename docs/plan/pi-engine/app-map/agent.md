## 0. Headline findings

1. **Approvals do not use eve's approval mechanism.** Every gated tool raises its own card in a file store (`approvals.json`), polls it, and the macOS app answers over `/api/approvals`. The only eve approval hook used is the `approval` policy function on OpenAPI connections (`agent/lib/openapi-approval.ts:126-131`), and it never returns `"user-approval"`: it polls the same store and returns `approved`/`denied`. The only eve `input.requested` use is the built-in `ask_question` (kind `question`). See section 2.
2. **Commands do not run in just-bash.** `bash` runs `/bin/sh -c` on the real host under macOS `sandbox-exec` with a generated seatbelt profile (`agent/lib/sandbox.ts:302-397`). just-bash exists only because eve stages inbound file attachments in its sandbox (`agent/sandbox/sandbox.ts:31-33`, memory note `eve-attachments-need-just-bash`). No tool calls `ctx.getSandbox` (grep clean). Pi has no sandbox, so the seatbelt layer plus `command-risk.ts` plus the path guards are the safety net that must be carried over. See section 6.
3. **The eve surface used is small:** `defineTool` with zod `inputSchema` and `execute(input, ctx)`; ctx fields `session.id`, `session.turn.id`, `session.parent`, `session.auth.current.attributes`, `callId`, `abortSignal`, `channel.kind`. No `needsApproval`/`approval:` on tools, no `execution: "background"`, no `defineState` (only eve's own `todo` spread), no `getSandbox`.
4. **Model binding is a custom fetch wrapper**, not an eve feature: one `chatModel("workhorse")` handle per eve session, stamped with session/turn/request ids and a base64url `x-useful-selection` header (`agent/lib/router-fetch.ts:102-106`). See section 3.
5. **Tool count.** 36 files in `agent/tools/` = 34 real static tools + `connection_tools.ts` (dynamic, yields `find_tools` plus mounted MCP tools) + `plant_read.ts` (spike fixture, resolves to null in production). Model-visible baseline today: 34 + `find_tools` + eve's `ask_question`, `load_skill`, `agent`, `task_cancel` = 39, plus `connection_search` and OpenAPI operations when an OpenAPI connection exists, plus up to 40 MCP tools a session mounted (`shared/policy.ts:148`). Measured schema size: 19,487 chars authored + 3,506 eve = 22,993 (`scripts/tool-schema-size.mjs` output, run read-only with a scratch `UB_STATE_ROOT`).
6. **Dead or unreachable code today:** the MCP branches of `connections/registry.ts:definitionFor` (`:15-47`) can never be reached because `isEagerConnection` is `entry.kind === "openapi"` (`shared/connection-tools.ts:63-65`); `rail_action` keeps an `updateSection` alias for old prompts (`tools/rail_action.ts:212-214`); `invalidateOnRestart` has no production caller (only `spikes/s3/approvals.test.ts:127`).

## 2. Approvals end to end (brief item 1)

**Postures** (`WorkspacePermission` = `read_only` | `auto` | `full_access`, `shared/shell-store.ts:14`). A per-session grant `{sessionId, path|null, permission, selection}` is stamped into `workspace.json` by the web process before every turn (`web/lib/agent-exec.ts:229-251`, `syncSessionWorkspace`). The agent re-reads it at tool time (`agent/lib/workspace.ts:47-55`). No grant for a real session = `read_only` (fail closed); no session at all (tests) = `auto` (`:49`). `sessionPermission` (`agent/lib/permission.ts:24-35`) wraps this and resolves a sub-agent to its root's grant.

**What triggers a card** (all gates in code, none in eve):
- `bash` (`tools/bash.ts:137-157`): read-only lines (`readOnlyRisk(cmd) === null`) never ask in any mode. `read_only` refuses everything else. Auto in an attached folder: asks only when `commandRisk(cmd, root)` returns a reason (delete, history rewrite, escalation, inline payload, reach outside folder). Auto with no folder ("computer" scope): any non-read line asks. Full access: asks only when `wipeRisk` fires (disk, volume, home, top-level folder, formatting). No `sandbox-exec` on the system: every line asks (`:154-157`). Credential-looking text is refused before any card (`:36-64`, `:108-111`).
- `write_file` (`lib/write.ts:98-118`, `lib/workspace.ts:87-91`): full access never asks; auto asks except inside a folder, or for a brand-new file under the home; read_only throws `workspace_read_only`. Planted-config paths (`.claude/settings.json`, git hooks, etc.) refused in every mode (`write.ts:15-19`).
- In-app tools via `inAppGate(permission, irreversible)` (`permission.ts:46-50`): read_only refuses, full runs, auto runs unless irreversible (then asks). Irreversible: `delete_bot`, `clear_history`, `install_cli`. Everything else (memory upsert/delete, create/update/delete routine, run_routine, generate_image, rail_action removeSection, post_to_group, send_to_bot) runs in auto without a visible card but still writes and consumes an approval record.
- `connector_execute` (`connector-risk.ts:97-101`): reads run; writes/destructive ask in auto, run in full, refuse in read_only. Risk comes from the Composio slug words.
- Mounted MCP tools and OpenAPI ops (`connector-risk.ts:113-116`): read_only refuses, auto asks for every call including reads, full runs.
- Proposal tools (`propose_*`, `update_bot_profile`, `post_to_group`) are not in the approvals store: they write a proposal into `shared/agent-store.ts` that the owner confirms in the UI (always, even in Full access, `instructions.md:40`).

**Mechanism.** A tool computes `actionSha256` over `{tool, canonicalArgs, cwd, targetRevision, backend, toolVersion}` (`approvals.ts:187-197`), calls `ApprovalStore.request` (`:221-255`) to write a `pending` record (id `apr_<16 hex>`, TTL 5 min from `POLICY_APPROVAL_TTL_MS`, `shared/policy.ts:21`), then either `decide(id,"approve",hash)` immediately (auto-run paths, so every action leaves a record) or `waitUntilNotPending` (`:439-462`, polls the file every 250 ms inside `execute`). `executeIfApproved` (`:473-481`) calls `consume`, which requires the hash to match, status `approved`, and the record's `epoch` to equal this process's `BOOT_EPOCH` (`:26`, `:301-305`), then marks it `consumed` (replay = `approval_replay`). After a long wait the tool re-checks the workspace root and permission (`bash.ts:174-184`, `write.ts:109-117`, `permission.ts:60-76`) or the connection URL/allow-list (`openapi-approval.ts:101-106`, `connection_tools.ts:240-257`).

**How the prompt reaches the app and the answer returns.** Own channel, not eve: the macOS app polls `GET /api/approvals` (`macos/Sources/UsefulBotCore/BackendClient.swift:797`) which returns `listPending()` (`web/app/api/approvals/route.ts:26`); the owner's answer is `POST /api/approvals/:id` with `{decision, actionSha256}` (`BackendClient.swift:809`, `web/app/api/approvals/[id]/route.ts:35`) with CSRF and owner gate, calling `ApprovalStore.decide`. The Swift comment says it directly: "this app gates tools with its own approval cards" (`macos/Sources/UsefulBotCore/EveStream.swift:2480-2482`). Two processes (Next server decides, agent requests/consumes) share the file via a directory lock (`approvals.ts:155-178`, 5 s timeout, 2 s stale) and tmp+fsync+rename (`:415-436`).

**Persistence and restart.** `approvals.json` in app state (`statePath("approvals.json")`, override `UB_APPROVALS_PATH`, `approvals.ts:144-147`), mode 0600, settled records pruned 1 h past expiry. Restart behavior: an approved-but-unspent record from a previous boot cannot be consumed (epoch check turns it `expired`). A pending record whose tool died with the process stays visible in `listPending` until its 5 min TTL (no production caller of `invalidateOnRestart`), so the UI can show a ghost card for up to 5 min after a restart. A Stop in the app expires the session's cards via the eve proxy route (`web/app/eve/v1/[...path]/route.ts:68-88`, `expireSession`), root cancel also retires sub-agent cards.

**eve mechanisms actually used for HITL:** (a) built-in `ask_question` -> `input.requested` kind `question`, answered with `{"inputResponses":[{requestId,optionId}]}` through the eve proxy (`shared/eve-proxy.ts:151-190`, `web/app/eve/v1/[...path]/route.ts:229`, `BackendClient.swift:1620-1630`); (b) `approval` policy callback on OpenAPI connections only (`openapi-approval.ts`), returning `{type:"approved"|"denied"}`. Kind `tool-approval` and `session-limit` are parsed by Swift but never raised by this app (limits are off, `agent.ts:182`).

## 3. Model binding per turn (brief item 2)

- **Flow:** eve calls the `model` resolver at every `step.started` (`agent.ts:188-217`). It (1) ensures the turn snapshot, throwing `bot_context_missing` if the session is unbound/mismatched/failed (`:199-209`), (2) returns the cached per-session handle `routerModel(ctx.session.id, turnId)` (`session-model.ts:66-119`) and `modelContextWindowTokens` from the frozen selection (`:214`).
- **Handle:** `createOpenAICompatible({baseURL: routerApiBase(), apiKey: UB_ROUTER_DESKTOP_TOKEN, fetch: routerFetch(...)}).chatModel("workhorse")` (`agent.ts:156-162`). The model name is always the alias `workhorse`; the router alias map is `workhorse`/`reviewer` (`router/src/registry.ts:29`). Boot fails if the token is missing (`agent.ts:167-170`).
- **Headers sent on every attempt** (`router-fetch.ts:99-107`): `authorization` (apiKey), `x-useful-session-id` = `stableUuid("session:"+eveSessionId)`, `x-useful-turn-id` = `stableUuid("turn:"+session+":"+eveTurn)` or random uuid when no turn id, `x-useful-request-id` = fresh `randomUUID()` per attempt (router refuses repeated ids as `duplicate_request`, `router/src/limits.ts:328`), and `x-useful-selection` = base64url JSON `{connectionId, modelId, effort|null, speed}` (`shared/session-selection.ts:27-69`, strict assert). Router validates ids as UUIDs and gates one model call per session (`router/src/index.ts:593-595`, `concurrency.acquire(key(caller, sessionId))` at `:627`), reads and resolves the selection only for the `workhorse` alias (`:604-615`). `UB_SESSION_ID`/`UB_TURN_ID` env pin the ids for probes (`router-identity.ts:40-41`).
- **Frozen per turn:** the selection is chosen once per turn id (snapshot `buildSnapshot` -> `botSelection(bot, store)` = bot's own `model` else `lastPick(store)`, window from `windowTokensFor`, `turn-snapshot.ts:277-298`) and held in the handle entry plus a process registry (cap 256) so retries, 429 waits, compaction calls and a handle evicted mid-turn reuse it (`session-model.ts:21-46`, `:84-98`). A pick made mid-turn applies next turn. With no turn id the grant's stamped selection is preferred over the live pick (`turn-snapshot.ts:291-296`); once-warned fallback (`session-model.ts:102-106`).
- **Window tokens:** `windowTokensFor` = catalog `contextTokens` for exactly that (connection, model), else 32,768 (`model-window.ts:11-14`, `shared/policy.ts:19`). eve compacts at 75% of that (`agent.ts:177`). Admission refuses a send that cannot fit (`shared/admission.ts`, `SHARED_PROMPT_CHARS` 9,100, `TOOL_SCHEMA_CHARS` 30,000, `OUTPUT_RESERVE_TOKENS` 4,096).
- **Bot binding:** eve session id -> bot id in `session-bindings` (shared). The web proxy injects `botId` into create bodies (`shared/eve-proxy.ts:88-89`), the channel JWT carries a `botId` claim and a `delivery` claim (`owner|handoff|routine`, `web/lib/agent-exec.ts:380-431`), `channel-auth.ts` checks claim == binding and first-claim ownership. All of this exists because one eve process serves many bots.
- **429 handling:** `waitHint` reads `error.code` + `retry_after_ms`; waits for `global_concurrency_limit`/`caller_rate_limit` up to 60 s total (30 s single), `upstream_rate_limited` up to 180 s (90 s single), jitter, cancels body, honors abort (`router-fetch.ts:11-27`, `:108-136`).
- **Model-calling tools** also stamp ids: `web_search`, `generate_image`, `review` via `toolRouterIds(ctx)` (`router-identity.ts:71-75`).

**What Pi needs (options, none verified in code):**
- A provider registered with `pi.registerProvider` or `models.json` pointing at `routerApiBase()`, bearer = desktop token (custom-provider.md:12, 30-42).
- Per-request ids: `before_provider_headers` mutates headers in place per model request (extensions.md:98, 208). Open question to test: does it fire per automatic retry, so each attempt gets a fresh `x-useful-request-id`? The router rejects a repeated id.
- Selection: either (a) set `x-useful-selection` in `before_provider_headers` from a value frozen at `before_agent_start` (one Pi run covers many turns; freeze there), (b) register one Pi model per catalog (connection, model) with model-level static headers (custom-provider.md:120 mentions model-specific headers) which also gives each model the right `contextWindow` so Pi's compaction uses the correct window, or (c) change the router to read connection+model+effort from the standard request (model string, reasoning param) and drop the custom header. (b)+(c) remove the need for dynamic window plumbing.
- Compaction: Pi triggers at `contextTokens > contextWindow - reserveTokens` (default 16,384, compaction.md:30-35), not a 75% rule; to keep 75% set `reserveTokens` per model or accept the change. `session_before_compact` can supply a custom summary/model (compaction.md:297-368).
- 429 waiting: unknown whether Pi's retry honors `retry_after_ms`; otherwise `routerFetch` must wrap the provider's HTTP layer (custom provider can delegate streaming, custom-provider.md:168, unverified that fetch is injectable).
- Virtual models (virtual-models.md) route a selected model to a physical one per request but do not solve headers by themselves.

## 6. Bash / sandbox / files / just-bash (brief item 5)

- **Where bash executes:** `runCommand(args, {cwd: root, env, ...})` spawns the argv from `confinedCommand` or `approvedCommand`: `["/usr/bin/sandbox-exec","-p",<profile>,"/bin/sh","-c",command]` (`lib/sandbox.ts:366-397`). Real host shell, real filesystem, owner's PATH (`ownerPath()`) and real HOME (`bash.ts:107`, `:229-247`); env is a whitelist (PATH, HOME, TMPDIR, LANG, TERM=dumb, SHELL, USER/LOGNAME, TZ), never `...process.env`, so router credentials do not reach children. stdin closed, own process group killed on timeout/abort, 30 s default, 30 min max, collection cap 1 MB per stream, model gets 32 KB per stream, `exitCode` 124 on timeout (`run-command.ts`, `bash.ts:20-29`, `:255-269`).
- **Three profiles:** (1) confined: `(deny file-write*)` except the root, temp/cache, `/dev`, plus protected-name denies (credential names, app state folders, runtime install dirs, shell startup files) and read denies for credential names (`sandbox.ts:302-363`); a read-only line gets `root = null` (no writes at all). (2) unbounded (Full access): allow-writes everywhere except system paths, protected names, planted config; plus credential store allows only for a lone registered CLI line (`credentialPathsFor`, `cli-registry.ts:250-262`). (3) approved line (owner approved the card): `allow default` minus planted-config and PATH-dir write denies (`sandbox.ts:382-397`); throws if no sandbox rather than run bare.
- **Text tripwires** before any card: `FORBIDDEN_PATH_SUBSTRINGS` (`.env`, `secrets`, `.ssh`, `.aws`, ...), `/etc`, `/private/etc`, `/var/db`, keychains, cookies, `..` in scoped postures, app state dir mentions (`bash.ts:36-64`).
- **File tools do not use the shell or just-bash:** `read_file`/`list_dir`/`write_file` call `node:fs` after `resolveWorkspacePath` (lexical escape check, forbidden substrings and exact segment names, runtime install paths, lstat walk that rejects any symlink component, `workspace.ts:117-151`) and `effectiveRoot`/`assertSafeRoot` (grant folder must be a real directory, not a symlink, not a credential-named folder, `:63-78`). Writes are atomic (tmp 0600 + fsync + rename) with parent symlink and realpath rechecks, planted-config refusal, 64 KB cap, optional `expectedSha256` conflict check (`write.ts:162-213`). Reads cap 16 KB (`shared/policy.ts:41`).
- **Workspace roots:** grant `path` = attached folder (`scope:"folder"`), else `UB_WORKSPACE_ROOT` or the owner's home (`scope:"computer"`, `workspace.ts:20-23`, `:50-52`). `list_dir` and `read_file` are limited to that root; `bash` is unbounded in Full access.
- **just-bash:** `agent/sandbox/sandbox.ts` selects `justbash({autoInstall:false})`; `shared/sandbox.ts` decides backend by the runtime config pin, otherwise sniffs docker/microsandbox and refuses to run on a "present but uncertified VM" (`sandbox/sandbox.ts:18-29`). The string `"just-bash"` is also written into approval hashes as `backend` (`bash.ts:124`, `write.ts:81`, `install_cli.ts:78`), a label only. `package.json` carries `just-bash` 3.4.2 and `scripts/patch-eve.mjs`. Nothing in `agent/` uses the eve sandbox API.
- **Pi consequences:** Pi runs with the user's permissions and no sandbox (security.md:1-10). Pi built-ins `read, bash, edit, write, grep, find, ls` (settings.md:42-46) would bypass `resolveWorkspacePath`, the seatbelt profile and `command-risk`. So: set `defaultTools: []` and register our own `bash`/`read_file`/`write_file`/`list_dir` custom tools (same names to keep instructions stable), or keep Pi's tools and route them through our logic with a `tool_call` gate and the tool `operations` hook (the `ssh.ts` example reuses tool operation interfaces, extensions.md:397; whether `bash` execution can be redirected to `sandbox-exec` this way is unverified). The seatbelt layer is macOS-only, as is the app.
