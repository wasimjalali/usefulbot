# UB-009 PR C: the new shared prompt, before and after (2026-10-02)

## The question

PR C replaces the 2,942-word shared prompt every bot reads with the 950-word text the model council approved, moves long procedures into two skills (`connect-apps`, `about-useful-bot`) and trims the tool descriptions. Two questions:

1. How much smaller is the fixed part of every request?
2. Do bots behave as well, or better, with the shorter text?

## What ran

- **App:** Useful Bot Dev on this Mac, never the daily app. "Before" is `main` after PR B (#176, `f30a0b7`). "After" is `feat/ub009-pr-c-texts` (#177): first at `994d325`, then again at `0144302` after the fix below.
- **Model:** GLM 5.3 Flash via OpenCode, the dev app's default. Permission Auto, no folder.
- **Payload:** the router's dev-only payload probe (`UB_PAYLOAD_PROBE_DIR`) dumped every request body sent upstream. One fixed probe turn on Test Bot per side.
- **Behaviour:** 30 owner messages (`behavior-scenarios.json`) in seven groups:
  - ask versus act;
  - honest limits;
  - verification;
  - refusal wording;
  - connect-app questions;
  - questions about the app;
  - identity and memory.

  They went in order to a fresh teammate bot with no instructions, through the macOS app. `run-behavior.py` drives the app in the background with cua-driver: it waits for each turn to end and declines any approval card so the run keeps moving. `summarize-behavior.py` rebuilds each scenario's reply and tool calls from the dumps.
- **Judging:** a blind per-scenario comparison by a Sonnet 5.5 judge (`judge-before2-vs-after2.json`), scoring correct, honest limits, ask versus act, helpful and style from 1 to 5, plus a winner.
- **Cost:** model turns ran on the OpenCode Go plan already paid for, so no per-token spend was recorded. Reviews and judging ran on existing Codex and Claude plans.

## Payload: the fixed envelope per request

| | Before | After | Change |
|---|---|---|---|
| System message (Test Bot) | 18,068 chars | 8,119 chars | −55% |
| of which the shared prefix | 17,393 | 7,444 | −57% |
| of which the bot's context block | 675 | 675 | 0 |
| Tools array as sent (37 tools) | 29,288 chars | 26,434 chars | −10% |
| Fixed envelope | 47,356 chars | 34,553 chars | −27% |

At the app's estimate of 3.5 characters per token, that is about 13.5k tokens before and 9.9k after. The admission check's constants now come from these numbers, with headroom: `SHARED_PROMPT_CHARS` 8,000 and `TOOL_SCHEMA_CHARS` 28,000. Before, they were 17,089 and 30,483. So a model window about 4k tokens smaller than before now fits.

The tool trims, measured description plus schema per authored tool with `scripts/tool-schema-size.mjs`: 20,309 down to 19,538 characters (the tables are in `tool-schemas-before.txt` and `tool-schemas-after.txt`). eve's `todo` is overridden with shorter text. Most of the remaining weight is schema structure, not words.

## What the runs found, and what changed because of them

1. **The em-dash rule regressed under the new prompt.**
   - The old prompt stated "Never use an em dash" on its own line near the top. The approved text buried "No em dashes." in its last section, and GLM Flash ignored it in 22 of 28 replies.
   - Fix (`0144302`): the Writing section now sits right after How you work and names the character and its replacements. After 2 had 0 of 29.
2. **`memory_upsert` was unusable for GLM.**
   - The model sent the string `"null"` for `expectedRevision` and `expiresAt`. Every call failed validation, and the bot honestly reported it could not save.
   - Fix (`5d128fb`, `56aa127`): the memory and write tools read `"null"`, `""` or a missing value as null, accept integer strings, and still refuse bad values. After 2 saved on the first call.
3. **A skill file took every bot down.**
   - An unquoted YAML description holding ": " made eve refuse to start, which showed as "The local services did not all start".
   - Fix (`994d325`, `7ab7994`): both descriptions are quoted, and a test lowers every `SKILL.md` with eve's own `lowerSkillMarkdown`.
4. **Two losses for the new text, both fixed in the tool descriptions (`feedc75`).**
   - R1 ("Delete every bot I have"): the teammate offered to delete them after confirming, although only the main bot can. `delete_bot`, `clear_history`, `propose_bot`, `propose_group` and `rail_action` now say who may act.
   - S3: the bot raised a Connect server card with a placeholder `example.invalid` URL. `propose_connection` now says to use only a URL the owner gave or an official source documents.
5. **Skills are found when they matter.** After 2 loaded `connect-apps` for the Gmail question and `about-useful-bot` for "What is Useful Bot?". Before, the same material sat in every request.

## Conclusion

The new shared prompt cuts the fixed envelope by about a quarter (a 55% smaller system message) with no measurable loss in reply quality on these 27 scenarios. The judge called it level, with slightly better ask-versus-act and style and slightly lower correctness. The run also surfaced four defects: the em-dash placement, the memory input bug, the skill YAML and two tool-text gaps. All are fixed in PR C.

This is one model, one run per side and a stateful sequence, so a 5-to-4 split is within noise. The plan's larger evals are not run here: the 8B local model, compaction, cold start at scale and the cache run.
