# 2026-10-01: a model council designs the agent instructions and per-bot context (UB-009)

## Question

The default Generalist's prompt was "too basic". The source audit (`docs/audit/UB-009-GENERALIST-PROMPT.md`)
found a bigger problem:
- Every bot shared one 2,942-word system prompt, written partly as a developer's coding rules.
- The Generalist's description never reached the model.
- A teammate's description rode as a user-message prefix that compaction could drop.
- Memory notes weren't scoped per bot.
- Two security gates the prompt claimed didn't exist in code.

The owner asked for a council of models to design the replacement before anything was built.

**Inputs:** a 138 KB packet (`packet.md`), containing:
- the audit;
- the current prompt and per-turn lines;
- the bot model and memory tools;
- eve's docs on instructions, memory and compaction;
- the owner's direction;
- the questions A1-A7 and B1-B8.

The exact commands are in the chair's session. The prompts are in `round1/prompt.txt` and `round2/prompt.txt`.

**Cost:** no API spend. Codex and OpenCode Go ran on the owner's subscriptions, Space Bunny is free, and the Claude seats ran inside the Claude Code session.

## Results

- **Round 1 agreement:** five independent proposals agreed on the core design.
  - The description becomes trusted, system-role context on every turn.
  - The shared prompt shrinks and drops the developer laws.
  - Tool names are fixed (snake_case).
  - Memory is scoped per bot.
  - The security gaps are fixed in code first.
- **Round 1 unique catches:**
  - GPT-6.1-Sol: approved `bash` lines bypass the sandbox; `memory_upsert` can overwrite another bot's note.
  - Sonnet: the first-turn binding race; the 500-character clip on every read.
  - Space Bunny: sub-agents run on the wrong folder and tag notes to the selected bot.
  - Muse: the Excalidraw path breaks under a blanket MCP rule.
- **A false claim, caught by the chair:** Space Bunny said handoffs get the identity prefix twice. `runEveTurn` posts to eve's own port, not the proxy.
- **Round 2:** 65 findings across three seats.
  - The biggest: the first-turn binding (Sonnet and Muse, independently).
  - Session grants are evicted, so they can't hold ownership (GPT).
  - A write-on-read migration would deadlock (Sonnet and GPT).
  - Pinned notes could launder model text into the system prompt (Sonnet and GPT).
  - Teammates could reach other bots through routines (Sonnet and GPT).
  - Prompt claims were still false: `read_file` and the tripwire, and Full access with proposals (all three).
- **Final check:** Fable 5.1 confirmed two premises from eve's dist files: custom JWT claims reach `auth.current.attributes`, and connection `approval` takes a custom async policy. It found 3 highs: an unbounded notes block, an unguided first run without a Composio key, and the PR order.
- **Prompt size:** the shared prompt went from 2,942 to 920 words (`wc -w`).

## Conclusion and what changed

- The final plan is `docs/plan/UB-009-AGENT-CONTEXT-PLAN.md`, with texts in `final/`, waiting for the owner's approval.
- Owner input changed two things mid-council:
  - Memory notes are the bot's own and load every session (6 recent in full, the rest as titles).
  - The Settings pane needed a designed layout: a mockup was made and revised once.
- **Process lessons:**
  - Run long OpenCode seats with a background timeout above their cap, or the runner kills them.
  - Tell read-only OpenCode seats not to touch `/tmp`, or a rejected call ends the session silently.
  - A free model's proposal can be strong (Space Bunny's round 1 was), but each claim still needs checking.
