## DISMISSED

- **`settled()` fast path skipping a late-appearing choice's own think block**: documented in the doc comment and covered by the pinned `n=1` assumption (verified). A second choice arriving after settle passes through byte-for-byte, which is the intended behavior.
- **`gap` mode `trimStart()` dropping the answer's first-line indentation** (e.g. `</think>\n\n  indented`): intended per the "dropping the blank lines" comment; cosmetic.
- **`content: ""` emitted on chunks whose text was fully held or absorbed into reasoning**: valid chunk schema; the AI SDK tolerates empty-string deltas.
- **`flushThinkStream` when `stream.template` is null**: held state can only exist after a parseable chunk with `choices` arrived, and that parse sets the template, so the null-guard never loses real held text.
- **Double flush**: `[DONE]` inside `splitThinkBlock` flushes inline; the end-of-stream `flushThinkStream` then finds every state `"text"` and returns null. Safe.
- **`finish_reason` on a delta-less or non-record-delta chunk**: `flush` runs, `target = {}` becomes `choice.delta`, producing `{"index":N,"delta":{"reasoning_content":...},"finish_reason":...}` — valid schema.
- **SSE framing of the flushed chunk**: `${held}\n\n${line}` inside the block plus the outer `\n\n` yields `data: {synthetic}\n\ndata: [DONE]\n\n` — two well-formed events, and `JSON.stringify` escapes newlines so held text cannot inject extra `data:` lines.
- **Non-streamed mutation vs. `content-length`**: `outHeaders` carries only `x-useful-*` headers (index.ts:632-636) and `send()` serializes the mutated JSON fresh — no stale length forwarded.
- **`rewrapThinkHistory` on non-string content**: assistant array content is rejected by `validateMessages` (verified); `content: null` with tool_calls becomes `"<think>…</think>"`, which is the shape MiniMax asks for and is asserted by the test.
- **`rewrapThinkHistory` dropping `reasoning_content` when content already opens with a think block**: the documented de-dup ("keeps it and drops the duplicate"); the alternative merge would double-report thinking.
- **Learned-key alignment**: `upstream.providerId`/`upstream.model` (index.ts) vs `resolved.providerId`/`resolved.model` (opencode.ts) — verified to line up.
- **`noteInlineThink` race**: single-threaded; two concurrent streams can double-log `inline_think_learned`, harmless.
- **A model that stops writing inline think stays flagged**: it keeps receiving thinking as `<think>` in content, which is exactly the shape MiniMax documents; no corruption.
- **Mislearning**: a model whose answer legitimately opens with literal `<think>…</think>` gets flagged, but rewrap only acts on messages that carry `reasoning_content`, so a non-thinking model's history is untouched.
- **`durableIds` skip before `consume` in Transcript.merge leaking a count**: pre-existing ordering, identical before this diff; the new `shown.isEmpty` branch increments the same counter the append path does, keeping both sides consistent — a leaked count can only ever suppress a message with identical raw text, which would have been suppressed by the same rule anyway.

- **`stripThreadPrefix` before `withoutLeadingThink`** in the durable pass: correct order — a stored prefix would otherwise hide the tag.
- **Held-text release paths**: finish reason (in-chunk flush), `[DONE]` (in-block flush before the line), end-of-stream (`flushThinkStream`), and `inside`-mode hold-back bounded to `close.length - 1` with the longest-suffix loop correct on the off-by-one.

- **Ordering with `settleStreamBlock`**: the think split runs on its output, so synthesized finish lines are parsed and release held text correctly.
