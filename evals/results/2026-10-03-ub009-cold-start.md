# UB-009 evals: 20 cold starts with the session stamp delayed and missing (2026-10-04)

## The question

UB-009 plan section 9: open 20 new teammate sessions, with the session-to-bot stamp delayed and with it missing. Each first request must carry the bot block. Otherwise the send must be refused before eve, because a turn eve accepts and then fails retires the session.

## What is the stamp

A new session gets its owner in two ways:
1. **The binding.** The proxy writes `session-owners.json` right after eve creates the session (`web/app/eve/v1/[...path]/route.ts`).
2. **The claim.** The turn's own channel token carries the bot (`web/lib/agent-exec.ts` `signChannelJwt`). The turn's resolver binds an unbound session from that claim (`agent/lib/turn-snapshot.ts` `boundBotId`).

A turn with neither waits up to 5 s for a binding, then refuses (`bot_context_missing`).

## What ran

**Dev-only overrides, never committed.** `2026-10-03-ub009-evals/coldstart-overrides.py apply` patches those two files. They read `~/.useful-bot-dev-app/coldstart-mode` on every request:
- `defer`: the proxy writes the binding 4 s after the create, without waiting, so the first turn starts before it exists;
- `skip`: the proxy never writes it;
- `noclaim`: `skip`, and owner tokens carry no bot claim.

Every edit asserts it matched exactly once. The flow was apply, `npm run build:dev-app && npm run install:dev-app`, the runs, then `git checkout --` of both files. The flag file was removed afterwards.

**App:** Useful Bot Dev with the payload probe. Test Bot on GLM 5.3 Flash, permission Auto.

**Turns** (`turns-cold-*.json`, sent with `run-turns.py`). Each turn says "Cold start <mode> N. Reply with the single word ready, then use your clear_history tool to clear your own chat." The driver approves the clear card, so the next send opens a brand-new session. A clear before the first run made it start cold too.
- defer: 10 turns;
- skip: 12 turns;
- noclaim: 3 turns.

**Check:** `cold-check.py <start> <end> <out.json> <instructions marker>` (marker `MANGO`: Test Bot's instructions during the runs ended with that word, set by the compaction eval's edit).
- New sessions come from the override's log line plus the binding store's `createdAt`.
- Each session's first request is the probe dump written at its first turn. It must hold the "Your bot" block with Test Bot's current instructions.
- Refusal lines come from all three service logs.

**Cost:** about 25 short turns on the OpenCode Go plan already paid for.

In defer mode, two turns (D01, D04) answered "ready" but didn't call `clear_history`, so their next turn reused the session. That's why there are 8 new sessions from 10 turns. The 12 skip turns made the total 20.

## What the run found

1. **Pass.** A late or missing binding never left a turn without its bot. The claim binds the session before the first model call.
2. **Pass.** With no claim and no binding, the send is refused before a turn runs. Here the refusal came from eve's channel auth, which answers 403 to a create without a claim (`agent/lib/channel-auth.ts`), not from the in-turn `bot_context_missing` backstop. The web proxy relays the 403 without logging it, so the committed evidence is the absence of any dump, request, binding or create:
   - no model request is made;
   - no session is created, so none is retired;
   - the app shows "The local server answered with status 403."
3. **Two observations from the refused sends,** reachable only through the override, since every real send carries a claim:
   - The note's wording is generic.
   - After the note is dismissed, the three unsent messages stay in the chat as ordinary sent bubbles with no failure mark. That gap is in the app's failure display for sends refused before eve, and it predates UB-009 (screenshot: `ub009-cold-noclaim.png`, repo root, not committed).

There was no normal-mode control run: the proxy's binding is the path every earlier eval and daily use already exercise.

## Conclusion

Cold start is safe:
- 20 of 20 new sessions carried the bot block on their first request, with the stamp delayed or missing;
- a send with no claim is refused before any model call;
- no session was retired.
