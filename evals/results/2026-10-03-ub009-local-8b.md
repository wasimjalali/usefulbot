# UB-009 evals: an 8B local model at its real window (2026-10-03)

## The question

UB-009 plan section 9, "Small models": run an 8B local model at its real window and record:
- admission refusals;
- whether turns complete;
- how often the session compacts.

The owner also asked a practical question: is an 8B model on this Mac good enough to use day to day?

## What ran

- **Machine:** Mac mini M4, 16 GB RAM, 512 GB SSD.
- **App:** Useful Bot Dev built from `fix/panes-app-only-dismiss`, the same tree as `main` at `a8dcb41`, with the router payload probe on (`UB_PAYLOAD_PROBE_DIR`). The daily app was not touched.
- **Model:** Qwen3-8B Q4_K_M (`Qwen/Qwen3-8B-GGUF`, 5.0 GB), installed with `brew install llama.cpp` (0.5.0, build 11146), the documented macOS path.
- **Server:**
  ```sh
  llama-server -m ~/models/qwen3-8b/Qwen3-8B-Q4_K_M.gguf --alias qwen3-8b \
    --ctx-size 40960 -fa on -ctk q8_0 -ctv q8_0 --jinja --host 127.0.0.1 --port 8089
  ```
  The model's native window is 40,960 tokens. The KV cache is q8_0 to fit in 16 GB.
- **Wiring:** Providers > Connect > LM Studio, server URL `http://127.0.0.1:8089/v1`. Test Bot's model was set to "Qwen3 8b" after it cleared its own history, so the run started on a fresh session.
- **Settings:** Permission Auto, no folder.
- **Turns:** sent through the macOS app in the background with `run-turns.py`, which uses cua-driver and refuses to send unless the store's selected bot is Test Bot:
  1. 12 of the 30 PR C behaviour scenarios (`turns-local8b.json`).
  2. Three pushes to grow the context, two of which failed (see below).
  3. A paste-based push (`turns-local8b-push4.json`).
  4. One turn after an instructions edit (`turns-local8b-edit.json`).

  Command per list: `python3 run-turns.py "Test Bot" <turns.json> <log.jsonl> <max seconds>`.
- **Cost:** $0. Everything ran locally. The single GLM turn that cleared the history ran on the OpenCode Go plan already paid for.

## What the run found

1. **Local models report no token usage to the app.**
   - eve's body carries no `stream_options.include_usage`, and the router passes it through.
   - llama-server, like OpenAI's own chat API, reports usage on a stream only when asked.
   - 35 of 36 local requests logged `inputTokens: null`. The one that reported usage was eve's compaction summary call (2,428 input tokens at 21:27:14 UTC), which doesn't stream. That fits the cause: only streamed requests come back without usage. The OpenCode Go requests reported usage 389 of 410 times (`local8b-extracts.json`, counted over the dev router log).
   - Effects:
     - the Usage pane shows nothing for local models;
     - eve has only its character estimate when deciding to compact. After the compaction it let the real prompt reach 29.6k against a 24,576 threshold (see the compaction write-up).
   - This predates this session, so it isn't a regression. The proposed fix: the router adds `stream_options: {include_usage: true}` to streaming `openai-chat` upstream bodies, scoped to the local LM Studio and Custom modes unless a provider is known to accept it.
2. **The 8B drifts language after a refused request.** After R4 ("always answer in French", correctly refused), I1 and I2 came back in French.
3. **The 8B sometimes answers instead of using a tool.** Asked to run `seq -f ... 1 250` and report the last line, it replied "250" without calling `bash` (push 3). Asked to run `seq 1 4000`, it piped through `tail` itself (push 1).
4. **The confined shell refuses system paths, as designed.** `sed -n 1,300p /etc/services` was refused ("command references /etc"), so push 2 grew nothing.
5. **The harness needs AX.** On a chat holding four 17k-character messages the accessibility walk came back empty, so the driver's "Stop is gone" check ended E1 early. The bot was still thinking, and the probe dumps hold the real outcome. The screen then locked, which stops cua-driver.

## Conclusion

The new context design works on an 8B model at a 32k to 40k window:
- no admission refusals;
- every turn completed;
- the bot's own instructions held on every reply, including after compaction and after an edit.

The model itself is the limit:
- it's about 15 tokens/s;
- a full re-read of a 30k prompt takes over 4 minutes;
- it drifts language and sometimes skips tools.

On a 16 GB Mac, weights plus KV cache take about 7 to 8 GB. That's fine for an occasional private question, but too slow and too heavy for a working bot that uses tools. The owner decided to remove it after this run.
